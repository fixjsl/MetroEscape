# 5.1 요약 — 작성 원칙과 초안

## 원칙

**5.1은 새 내용을 담지 않는다.** 1장의 문제 제기, 3장의 설계, 4장의 결과를 한 바퀴로 잇는 것이 전부다. 여기서 처음 나오는 주장이 있으면 근거가 없는 문장이 된다.

**숫자는 4장에서 측정한 것만 쓴다.** 스크립트 122개, 조명 패스 프레임 기여도 1% 미만, SSAO 적용 시 프레임 시간 9.2% 증가 등 4장 표에 있는 값만 인용한다.

**말할 수 없는 것을 구분한다.** 본 연구에는 플레이테스트가 없다. 따라서 "반복 실패가 좌절로 이어지지 않음을 확인하였다", "재도전 동기가 유지되었다" 같은 문장은 쓸 수 없다. 4장이 뒷받침하는 것은 *구조를 설계하고 구현하였으며 그것이 의도대로 동작한다*까지다. 그 구조가 실제 플레이어 경험에 미치는 효과는 측정하지 않았으므로 5.2에서 한계로 넘긴다.

**분량** — 학사논문 기준 한 쪽 안쪽, 네 문단이면 충분하다.

## 초안

### 5.1 요약

 본 연구는 실시간 서바이벌 게임에서 불가피하게 반복되는 실패를, 플레이어가 누적된 좌절이 아니라 구조화된 진행으로 경험하도록 하는 설계를 다루었다. 단 한 번의 사망이 전체 진행을 초기화하는 처리 방식은 재도전 의지를 꺾을 수 있고, 반대로 실패의 대가가 지나치게 가벼우면 긴장이 유지되지 않는다. 이 문제에 대해 본 연구는 런(Run), 세션(Session), 메타 프로그레션(Meta-progression)의 세 층위를 중첩하고 각 층위에 독립적인 리셋 경계를 두어, 하위 층위의 실패가 상위 층위로 전이되지 않도록 하는 구조를 제안하고 Unity 기반으로 구현하였다.

 구현한 시스템은 기능별로 분리된 여섯 개의 계층으로 구성된다. 런 층위에서는 기지에서 출발하여 자원과 열쇠를 확보하고 비상구로 귀환하는 익스트랙션 루프를 구현하였으며, 사망 시 소지 아이템의 75%를 잃고 기지에서 재개하는 체크포인트형 처리와 세 회의 목숨을 모두 소진했을 때의 세션 종료를 순차적으로 결합하였다. 세션 층위에서는 보스 처치로 획득한 열쇠가 블록에이드를 해제하여 구역을 개방하고, 개방된 구역에 대한 빠른 이동이 세션 동안 유지되도록 하였다. 메타 프로그레션 층위에서는 전투, 수집, 탐색의 세 축에 대한 세션 내 지표가 임계값에 도달하면 특성이 해금되고, 해금 기록만이 세션 경계를 넘어 보존되어 다음 세션에 최대 두 종을 이월할 수 있도록 하였다. 이와 함께 실시간 생존 액션의 기반으로 단일 계층 FSM 기반의 플레이어·몬스터·보스 제어, 소음과 빛을 입력으로 받는 연속적 탐지 게이지, 입력 버퍼링과 캔슬 윈도우를 갖춘 근접 전투, 재료 기반의 확정적 크래프팅을 구현하였다. 폐쇄된 지하철이라는 배경에 대해서는 URP의 사용자 정의 렌더 패스를 삽입하여 조명을 화면 공간에서 단일 패스로 합성하였다.

 4장에서는 구현 결과를 세 가지 방식으로 확인하였다. 첫째, 3장에서 설계한 아홉 개 기능의 구현 현황을 정리하고, 여섯 계층이 실제 스크립트 122개에 어떻게 대응하는지를 제시하였다. 둘째, 계층 분리가 콘텐츠 추가 비용에 미치는 영향을 확장 대상별 코드 변경량으로 측정하였다. 데이터 계층에서 완결되는 확장은 코드 변경을 요구하지 않았고, 단일 계층의 추상 규약을 구현하는 확장은 새 파일 하나만을 요구하였으며, 기존 코드의 수정을 요구한 것은 여러 계층에 걸친 구역 확장뿐이었다. 셋째, 조명 구조의 실행 비용을 측정하였다. 조명 합성 패스는 등록된 광원 수와 무관하게 프레임 시간의 1% 미만을 차지하였고, 광원 수에 비례하는 비용은 입력을 준비하는 CPU 측 단계에 국한되어 동시 처리 상한인 네 개에서도 0.32%에 그쳤다. 반면 설계 단계에서 함께 적용하였던 SSAO는 깊이·법선 프리패스로 인해 장면의 기하를 한 차례 더 렌더링하여 프레임 시간을 9.2% 증가시켰으며, 이는 장면의 오브젝트 수에 비례하는 부하를 회피하려던 조명 구조의 설계 의도와 상충하므로 최종 빌드에서 제거하였다.

 본 연구의 의의는 익스트랙션 루프와 메트로배니아식 공간 확장이라는 서로 다른 장르의 진행 구조를, 리셋 경계를 기준으로 층위를 나누어 하나의 게임 안에 결합하고 그 결합을 실행 가능한 형태로 구현하였다는 점에 있다. 또한 그 과정에서 기능 분리를 목적으로 설계한 계층 구조가 결과적으로 콘텐츠 확장 비용을 계층 경계 안에 가두는 방향으로 작동함을 코드 변경량으로 확인하였다.

## 쓰면 안 되는 문장

아래는 4장이 뒷받침하지 않는 주장이다. 5.1에 넣으면 근거 없는 단언이 된다.

| 쓰면 안 되는 문장 | 이유 |
|---|---|
| 반복 실패가 좌절로 이어지지 않음을 확인하였다 | 플레이테스트 없음 |
| 재도전 동기가 유지됨을 검증하였다 | 동일 |
| 플레이어가 세 축을 의식하며 플레이하게 되었다 | 동일 |
| 6개 구역까지 확장 가능함을 확인하였다 | 두 구역까지만 실증 |
| 새로운 구역을 코드 수정 없이 추가할 수 있다 | 기존 파일 2개 수정됨 |
| 최적화를 통해 성능이 향상되었다 | 미적용본과의 비교는 SSAO 한 건뿐 |

앞의 세 문장에 해당하는 내용은 **5.2에서 한계로** 쓴다. 예컨대 "본 연구는 시스템의 설계와 구현에 범위를 두었으며, 제안한 층위 구조가 실제 플레이어의 실패 경험과 재도전 동기에 미치는 효과는 측정하지 않았다. 이용자 대상 평가는 향후 과제로 남긴다" 정도다.

## 초록과의 관계

국문 초록은 "배경/목적 > 만든 것(시스템) > 방법 > 결과 > 의의" 순서로 지정되어 있다. 5.1과 구조가 거의 같으므로, **5.1을 먼저 쓰고 초록은 그것을 압축**하는 편이 효율적이다. 다만 두 글이 문장 단위로 같으면 곤란하므로 초록은 문단 구분 없이 한 덩어리로 줄이고, 5.1에 있는 구체 수치 가운데 한두 개만 남긴다.
